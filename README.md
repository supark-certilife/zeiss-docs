# 자이스 재주문 번호 연동 API 안내

> 작성일: 2026-10-07 · 관련 SPEC: SPEC-ZEISS-REORDER-CODE-001

자이스(CZV 올케어 프로그램)가 반품 접수 때 재주문 생산입수번호를 이 API로 보내면, 그 번호로 고객이 셀프 발급할 때 **인증서는 발급되고 쿠폰은 나가지 않습니다**(쿠폰 이중 발행 방지).

## 한눈에 보기

자이스는 번호를 보내기만 하면 되고, 쿠폰을 막는 일은 서티라이프가 합니다.

1. **반품 접수 (자이스 CZV)** — 올케어 반품을 접수하면서 재주문 제품의 생산입수번호(10자리)를 정합니다.
2. **번호 전달 (자이스 → 서티라이프)** — 이 문서의 등록 API로 그 번호를 보냅니다.
3. **저장 (서티라이프)** — 「쿠폰을 주지 않을 번호」로 기억합니다.
4. **고객 셀프 발급** — 고객이 새 렌즈를 받고 브랜드관에서 그 번호로 인증서를 발급하면, 인증서는 나가고 쿠폰은 나가지 않습니다. 고객 화면에는 쿠폰 칸이 나오지 않습니다.
5. **현황 확인 (자이스 관리자)** — 서티라이프 제조사 관리자 → 쿠폰 → 「재주문 번호」에서 보낸 번호와 상태를 볼 수 있습니다.

주소 정보는 받지 않습니다.

## 접속 정보

모든 요청은 HTTPS POST + JSON이고, 자이스 회사 전용 API 키를 헤더에 넣습니다.

| 환경 | 주소(Base URL) |
| --- | --- |
| 개발(테스트) | `https://intest-api.certi.life` |
| 스테이지 | `https://stg-api.certi.life` |
| 운영 | `https://api.certi.life` |

| 헤더 | 값 |
| --- | --- |
| `X-Api-Key` | 자이스 회사 API 키 (환경마다 다름, 서티라이프가 별도 전달) |
| `Content-Type` | `application/json` |

- API 키는 서티라이프 제조사 관리자 → API키 관리에서 발급하며, 자이스 회사 키만 통과합니다. 키를 삭제하면 즉시 막힙니다.
- 한 번에 최대 **500건**, 회사당 **분당 60회**까지 호출할 수 있습니다.
- 생산입수번호는 **숫자 10자리**만 받습니다(앞뒤 공백은 제거).
- 정의되지 않은 필드는 무시하므로, 다른 값을 함께 보내도 요청이 거부되지 않습니다.
- 같은 번호를 여러 번 보내도 안전합니다(한 번만 저장).

## 등록 API

`POST /v1/brand/zeiss/reorder-codes` — 재주문 번호를 한 건 또는 여러 건(최대 500) 보냅니다. 성공하면 200과 함께 **번호별 결과**를 돌려줍니다.

```http
POST https://api.certi.life/v1/brand/zeiss/reorder-codes
X-Api-Key: {자이스 API 키}
Content-Type: application/json

{
  "requestId": "CZV-20261007-0001",
  "items": [
    { "code": "1234567890", "originalCode": "0987654321" },
    { "code": "1234567891" }
  ]
}
```

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `items[].code` | 필수 | 재주문 제품의 생산입수번호, 숫자 10자리 |
| `items[].originalCode` | 선택 | 반품된 원래 제품 번호(기록용), 숫자 10자리 |
| `requestId` | 선택 | 자이스 쪽 추적용 요청 번호, 1~64자 |

```json
{
  "results": [
    { "code": "1234567890", "result": "registered" },
    { "code": "1234567891", "result": "issuedBeforeNotice", "issuedAt": "2026-10-01T14:03:00+09:00" }
  ]
}
```

| result | 뜻 | 자이스가 할 일 |
| --- | --- | --- |
| `registered` | 새로 등록됨. 이 번호로는 쿠폰이 나가지 않음 | 없음 |
| `duplicate` | 이미 등록된 번호 | 없음(재전송해도 안전) |
| `issuedBeforeNotice` | 통보보다 먼저 고객이 발급해 쿠폰이 이미 나감(회수하지 않음) | 필요하면 내부 확인 |
| `invalid` | 번호 형식이 틀림(`reason`에 사유). 이 번호만 저장되지 않음 | 번호를 고쳐서 다시 보냄 |

한 요청 안에 틀린 번호가 있어도 나머지 번호는 정상 처리됩니다.

## 해제 API

`POST /v1/brand/zeiss/reorder-codes/release` — 잘못 보낸 번호를 되돌릴 때만 씁니다. 고객이 발급하기 전에 해제하면 그 번호는 다시 정상적으로 쿠폰이 나갑니다.

```http
POST https://api.certi.life/v1/brand/zeiss/reorder-codes/release
X-Api-Key: {자이스 API 키}
Content-Type: application/json

{ "items": [ { "code": "1234567890" } ] }
```

```json
{ "results": [ { "code": "1234567890", "result": "released" } ] }
```

| result | 뜻 |
| --- | --- |
| `released` | 해제됨. 이후 이 번호로 발급하면 쿠폰이 정상적으로 나감 |
| `releasedAfterIssuance` | 해제됐지만, 이미 쿠폰 없이 발급된 뒤라 자동으로 쿠폰이 나가지는 않음(필요하면 서티라이프에 요청) |
| `alreadyReleased` | 이미 해제된 번호 |
| `notFound` | 등록된 적 없는 번호 |
| `invalid` | 번호 형식이 틀림 |

해제한 번호는 다시 등록 API로 보내면 재등록됩니다.

## 오류 코드와 재전송 기준

오류는 모두 `{ "statusCode", "errorCode", "message" }` 형태입니다. **5xx와 429는 같은 요청을 다시 보내면 되고**, 4xx(429 제외)는 요청을 고친 뒤 보냅니다.

| HTTP | errorCode | 원인 | 재전송 |
| --- | --- | --- | --- |
| 400 | `INVALID_REQUEST` | 본문 형식 오류(예: `items`가 비었음) | 고쳐서 |
| 400 | `BATCH_TOO_LARGE` | 한 번에 500건 초과 | 나눠서 |
| 401 | `UNAUTHORIZED` | API 키 없음 · 틀림 · 삭제됨 | 키 확인 후 |
| 403 | `FORBIDDEN` | 자이스가 아닌 회사의 키 | 키 확인 후 |
| 429 | `RATE_LIMITED` | 분당 60회 초과 | 1분 뒤 그대로 |
| 500 | `INTERNAL_ERROR` | 서티라이프 내부 일시 오류 | 그대로 |
| 502 | `UPSTREAM_UNAVAILABLE` | 서티라이프 내부 연결 실패 | 그대로 |
| 504 | `UPSTREAM_TIMEOUT` | 30초 안에 처리가 끝나지 않음 | 그대로(이미 저장됐어도 `duplicate`로 안전) |

재전송은 1분 간격으로 3~5회면 충분합니다. 그래도 실패하면 서티라이프에 알려 주세요.

## 언제 보내면 되나

**반품을 접수해 재주문 번호가 정해지는 즉시** 보내 주세요. 고객이 새 렌즈를 받기 전에 들어와 있어야 쿠폰이 막힙니다.

- **제때 보낸 경우** — 고객이 나중에 셀프 발급해도 쿠폰이 나가지 않습니다. 자이스 관리자 목록에는 「미발급 대기 → 발급됨-쿠폰 미지급」으로 보입니다.
- **늦게 보낸 경우** — 그사이 고객이 이미 발급해 쿠폰을 받았다면 쿠폰은 회수하지 않고, 응답에 `issuedBeforeNotice`와 발급 시각을 돌려줍니다. 관리자 목록에는 「통보 전 이미 발급됨」으로 표시됩니다.
- **모아서 보내도 됩니다** — 건별 호출과 묶음 호출(최대 500건) 모두 지원합니다. 다만 묶어서 보내는 간격이 길수록 늦은 통보가 생길 가능성이 커집니다.
